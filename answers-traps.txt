1、在 RISC-V 中，函数参数通常保存在寄存器 a0 到 a7 中。对于 printf 的调用，第一个参数是格式字符串，保存在 a0 中；第二个参数是 f(8) + 1，保存在 a1 中；第三个参数是 13，保存在 a2 中。

2、
对 f 的调用：
	在 main 的 C 代码中，f(8) + 1 被计算为 12。
	在汇编代码中，直接将 12 加载到寄存器 a1 中（li a1, 12）。
	因此，f 的调用被编译器优化掉了，没有显式的调用指令。
对 g 的调用：
	在 f 的汇编代码中，g(x) 的功能被内联优化为直接的 addiw 指令。
	因此，在 main 的汇编代码中也没有显式的对 g 的调用。

3、printf 函数的地址是通过 auipc ra, 0x0 和 jalr 1536(ra) 计算得到的。具体来说，auipc 指令将 ra 设置为 printf 的地址，然后 jalr 跳转到该地址执行。

1. auipc ra, 0x0 的作用
	指令解析：
	auipc（Add Upper Immediate to PC）将 20 位的立即数左移 12 位后，与当前 PC 的高 20 位相加，结果存入目标寄存器 ra。立即数为 0x0，因此 ra = (PC & 0xFFFFF000) + (0x0 << 12)，即 ra = PC 的当前值（忽略低 12 位）。
	
	实际效果：
	假设 auipc 指令的地址是 0x30，则执行后 ra = 0x30。
	目的：获取当前指令的地址基址，用于后续相对偏移计算。

2. jalr 1536(ra) 的作用
	指令解析：
	jalr（Jump and Link Register）跳转到 ra + 1536 的地址，并将返回地址（PC + 4）存入 ra。
	1536 是十进制值，对应十六进制 0x600。

	实际效果：
	计算跳转地址：ra + 0x600 = 0x30 + 0x600 = 0x630。
	0x630 是 printf 函数的入口地址。
	ra 更新：执行后 ra = 0x34 + 4 = 0x38（jalr 指令地址为 0x34，返回地址为下一条指令 0x38）。

3. 两条指令的协作流程
	获取当前指令基址：
	auipc ra, 0x0 将当前指令地址的基址（0x30）存入 ra。

	计算目标函数地址：
	jalr 1536(ra) 将 ra 的值加上 0x600，得到 printf 的绝对地址 0x630。

	跳转与返回地址保存：
	跳转到 0x630 执行 printf 函数。
	将返回地址 0x38 存入 ra，确保 printf 执行完毕后能返回到 main 函数继续执行。

4. 地址计算示例
	假设 auipc 位于 0x30：
	auipc ra, 0x0 → ra = 0x30（忽略低 12 位）。
	jalr 1536(ra) → 跳转地址 0x30 + 0x600 = 0x630。
	返回地址 ra = 0x34 + 4 = 0x38。

5. 设计意义
	位置无关代码（PIC）：
	通过 auipc + jalr 的组合，代码不依赖绝对地址，可在内存任意位置加载执行。


4、在 main 中 printf 的 jalr 之后，寄存器 ra 中保存的是返回地址，即 printf 函数执行完毕后应该返回的下一条指令的地址。在这个例子中，ra 的值是 0x34 + 4，具体计算需要结合代码的偏移量。

5、运行以下代码：
unsigned int i = 0x00646c72;
printf("H%x Wo%s", 57616, &i);
程序的输出是：
He110 World
这是因为：
0x00646c72 在内存中以小端存储为字节序列 72 6c 64 00，对应的 ASCII 字符是 r l d \0，但结合格式字符串 "H%x Wo%s"，%s 会从 &i 开始读取直到遇到 \0，所以会显示 "World"。
57616 是十进制数，转换为十六进制是 0xe110，在格式字符串中以 %x 输出为 e110，结合 "H" 和 " Wo"，最终输出 "He110 World"。
如果 RISC-V 是大端存储，为了得到相同的输出，需要将 i 设置为 0x726c6400，并将 57616 更改为 0x10e1（即 4321）。

6、在下面的代码中：
printf("x=%d y=%d", 3);
y= 之后将打印一个未定义的值。这是因为格式字符串中要求两个参数，但只提供了一个参数（3）。这种情况下，y 的值是未定义的，因为第二个参数没有被正确传递，可能会读取到垃圾值或引发其他未定义行为。
